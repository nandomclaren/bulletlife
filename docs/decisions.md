# Technical decisions

Short log of technical decisions. Newest last.

## 2026-10-18 · Phase 0 scaffold

- **Stack:** Vite 8 + React 19 + TypeScript, `vite-plugin-pwa` (generateSW, autoUpdate), Dexie 4 + `dexie-react-hooks`, `dexie-cloud-addon` for the sync test.
- **Hosting:** served from a **domain root only**. No sub-path deploys. `base` is fixed to `/` in `vite.config.ts`.
- **Routing:** real URLs via the History API so the system back gesture works in the installed app; scroll position is saved in `history.state` and restored on `popstate` (`history.scrollRestoration = 'manual'`). The spike uses a tiny hand-written router; revisit in Phase 1.
- **Strings:** every user-visible string lives in `src/i18n/en.ts`.
- **Long press:** Pointer Events + 500 ms timer (cancelled after 10 px of movement); `-webkit-touch-callout: none` and `user-select: none` on the bullet button only. Right click / Ctrl-click via `contextmenu`.
- **Caret color:** each line sets `--bullet` from its type and the editable text uses `caret-color: var(--bullet)` (spec section 8, "writing has to feel good").
- **Naming:** no third-party trademarks anywhere in code, UI, URLs or package names. The Markdown glyph option is called "Dot notation".
- **Spike code** lives in `src/spike/` and `src/data/spikeDb.ts` and is thrown away in Phase 1.

## 2026-10-18 · Hosting on Railway

- Fernando already uses Railway, so the app is deployed there instead of Cloudflare Pages.
- **Dockerfile** (multi-stage: `node:22-alpine` build → `caddy:2-alpine`) rather than Railpack auto-detection, so the build and the server config are explicit and reproducible locally.
- **Caddyfile:** `auto_https off` (Railway terminates TLS), listens on `$PORT`, SPA fallback with `try_files {path} /index.html`, `/assets/*` cached for a year as immutable, everything else `no-cache` so a new service worker reaches installed apps, manifest served as `application/manifest+json`.
- Verified locally with Caddy 2.10: headers as above, service worker takes control, deep link `/month/2026-10` loads offline.
- Cost: one always-on static container, a few MB of RAM. It fits the Hobby plan's included usage. Sync stays on Dexie Cloud. Railway could host a sync backend later if we leave Dexie Cloud (see section 11).

- The manager offered no free production user, only seat packs (25 for $3/month). Decide in Phase 2: pay the $3/month, or move to another backend (Instant, Jazz, or our own on Railway). The `src/data/` repository layer keeps that switch cheap.

## 2026-10-18 · Phase 1: editor prototypes

- Two prototypes with identical features, same line DOM and CSS, so the comparison is about the engine only:
  - **A · ProseMirror** (`src/proto/PmEditor.tsx`): raw ProseMirror (no TipTap layer), flat `line` nodes with `indent` as an attribute; derived classes (inherited color, chevrons, hidden subtrees) via node decorations; prefixes via input rules (Backspace right after undoes the conversion).
  - **B · Line editor** (`src/proto/LineEditor.tsx`): one contentEditable root; the browser edits text inside a line, structural edits are intercepted in `beforeinput` and applied to our model.
- **Flat list + indent** instead of nested lists: maps 1:1 to `Entry` (`parentId` derived from indentation, see `src/editor/lines.ts`), makes collapse a pure render concern, and keeps multi-line selection inside a single editing host.
- Shared, editor-agnostic logic lives in `src/editor/lines.ts` with unit tests (prefix matching, state cycle, color inheritance, collapse, indent rules).
- Routes: `/` prototype chooser, `/proto/a`, `/proto/b`, `/check` device check.
- Decision: see next entry.

## 2026-10-18 · Themes now, not in Phase 5

- Fernando asked for dark mode with a manual choice. Themes ship now: **Automatic** (follows the system, default), **Paper** (light), **Graphite** (dark), **Night** (OLED black), on a Settings page at `/settings`.
- Tokens are CSS variables switched by `data-theme` on `<html>`; no attribute = Automatic via `prefers-color-scheme`. An inline script in `index.html` applies the saved theme before first paint (no flash). `theme-color` follows the theme so the iOS status bar matches.

## 2026-10-18 · Editor decision: B (own line editor)

- **Chosen: B**, after Fernando wrote in both on the iPhone. B "wins easily": deleting a bullet behaves like editing text he controls, and he can freely type "-" or any other symbol. In A, Backspace over a bullet jumped back to the previous bullet.
- A (ProseMirror) and its dependencies were removed. B lives in `src/editor/LineEditor.tsx`; `/` now opens it until the real pages exist.
- Risk to watch with B: iOS autocorrect, dictation, predictive text and IME composition all go through our `beforeinput` handling. Test them on the iPhone as the editor grows.
- **iPhone indenting without Tab:** a space at the very start of a line indents it; Backspace at the start outdents first, then removes the bullet, then joins with the line above.
- **iOS form bar (^ v ✓) cannot be hidden by a web app.** A toolbar of our own above the keyboard kept fighting it (covered, then floating over the page while scrolling), so it was **dropped** (Fernando). Indent/outdent use space/Backspace at the line start; priority uses the `* ` prefix and the bullet menu. A native app can replace the system bar (`inputAccessoryView`); see CLAUDE.md section 14.

## 2026-10-18 · Phase 1 core, part 1: data and time pages

- **Repository** (`src/data/repo.ts`) is the only data entry point; Dexie lives in `src/data/db.ts`. Tables: `logs`, `entries` (`[logId+slot]` index), `settings`.
- **Deterministic ids for time logs** (`daily:2026-10-18`, `weekly:2026-W43`, `monthly:2026-10`, `future:2026`): two offline devices writing the same day never create two logs. Entries use ULIDs.
- **Lazy creation:** a log row is written only when its first non-blank entry is saved. Navigating never writes. A blank page (one empty line) is never stored.
- **Saving:** each editor saves its `(log, slot)` 400 ms after the last change, and flushes on page hide and unmount. Only changed entries are written (`diffEntries`); order uses fractional keys that are kept when still in order (`assignOrders`).
- **Flat lines ↔ entries:** the editor's indent becomes `parentId`; loading rebuilds indents from parents in order.
- **Weeks:** keys follow ISO-8601 numbering (`2026-W43`). With Sunday as first day, a week takes the number of the Monday after its Sunday. Routes: `/day/2026-10-18`, `/week/2026-W43`, `/month/2026-10`, `/year/2026`; `/` redirects to today's finest active log.
- **Month:** day rows are rendered from the date; each row is a compact editor storing entries with `slot = 'YYYY-MM-DD'`. "Month tasks" is the same log with an empty slot. Year: twelve editors with `slot = 'YYYY-MM'`.
- **Header:** breadcrumb of active levels, ‹ ›, Today, native date picker. Settings moved to a quiet footer link until the Index menu exists (the header must fit a 390 px iPhone).
- Still to do in Phase 1: Month row font shrink (85% then wrap), bullet menu, settings for active logs / event states / first day, Collections and Index, offline check of the whole flow.

## 2026-10-18 · No horizontal scrolling

- `html, body { overflow-x: clip; overscroll-behavior-x: none }` and `body { touch-action: pan-y pinch-zoom }`: nothing can push the page sideways, no sideways rubber-band on iOS, vertical panning and pinch zoom kept. Horizontal pointer moves still reach the app (Phase 4 swipes).
- The breadcrumb no longer scrolls: outer crumbs shrink with an ellipsis, the current one stays whole.
- Mac: Safari's two-finger swipe between pages is a system gesture; `overscroll-behavior-x` may not stop it in Safari (Chromium honors it). If it still fires, it can be turned off in macOS System Settings › Trackpad › More Gestures › Swipe between pages (affects all apps).

## 2026-10-18 · The page's free space belongs to the editor

- Each editor sits in an `.editor-area` tap target. A tap on free space puts the caret at the end of the last visible line (the first line on an empty page); a tap in a line's left margin puts it at the end of that line. Taps on text, bullets and chevrons are left alone.
- On Day and Week pages the area stretches to the bottom of the screen; Year month areas and Month day rows are whole tap targets too. The focus happens inside the tap, so iOS opens the keyboard.

## 2026-10-18 · Caret can no longer enter the gutter

- Bug (iPhone): Backspace on an empty first line moved the caret into the gutter and broke the line. WebKit lets the caret sit before a non-editable element at the start of the editing host.
- Fix in three layers: (1) the gutter is now absolutely positioned beside the text, outside the text flow, with the same top padding, font size and line height as the text so bullets still sit on the first baseline; (2) Backspace at a line start is handled in `keydown` (not only `beforeinput`, which WebKit may not let us cancel there); (3) a `selectionchange` guard moves any caret that lands outside `.line-text` back to the start of that line.

## 2026-10-18 · "* " on plain text stays text

- Bug: typing "* " on an empty plain line turned it into a priority mark in the gutter, which Backspace could not remove.
- Now a lone "* " marks priority only on a line that already has a bullet (as CLAUDE.md 3.4 says: "* " before a bullet). On plain text it stays a typed asterisk. "* . ", "* o. ", "* - " still create a priority task/event/note.
- Backspace at the start of a plain line that still carries a priority mark (older data) removes the mark first.

## 2026-10-18 · Phase 1 core, part 2: settings, bullet menu, Month text fit

- **Settings** (Dexie `settings` row): active logs Month / Week / Day with the "at least one" rule (`src/data/settings.ts`, unit tested; the last switch on is locked), Event states, First day of week (Monday / Sunday). Theme stays per device.
- **Event states off:** event bullets stop cycling (tap and ⌘↵ do nothing); a state already saved stays visible (CLAUDE.md 12: never hide data).
- **Bullet menu:** long press (500 ms, also click-and-hold) or right click / Ctrl-click on the bullet (right click anywhere in the margin for plain lines). One entry at a time: Type (Task, Event, Note, Text), State (Open, Complete, Cancel, Migrate, Schedule), Signifiers (Priority `*`, Inspiration `!`, Explore drawn eye), Indent, Outdent, Delete. Delete moves children up one level and shows an "Undo" toast for 5 s. "Copy as…" arrives with Phase 3.
- **Migrate / Schedule** set `placement = { status: 'pending' }` (cleared when the entry leaves those states), ready for the Pending panel in Phase 4.
- **Month text fit** (`src/pages/fitText.ts`): a phrase that does not fit one line shrinks continuously down to 85% (min 14 px), then wraps and the row grows. Never truncated.

## 2026-10-18 · Pages of a turned-off level redirect

- Bug: with only Week on, a Day page could still open (old link, history, or the app opening before Settings were read) and ‹ › stepped by day.
- Now a Day, Week or Month page whose level is off is replaced (history `replace`) by the finest active level for the same date. Opening the app waits for Settings to be read (`useLoadedSettings`) instead of using defaults.

## 2026-10-18 · Phase 1 part 3: Collections, Index, acceptance

- **Collections** are logs of kind `collection` with id `collection:<ULID>`, created only by "New collection" in the Index (explicit action) and renamed in place. Route `/collection/<id>`.
- **Index** (`/index`, button left of the breadcrumb) is derived: collections A–Z, then logs that have entries, grouped by year (Year, Month, Week, Day). Settings link moved there too (the footer link stays).
- **Scroll restore:** the browser's scroll anchoring shifted the restored position while a page's entries loaded (Month back from Day landed 136 px off). `overflow-anchor: none` on the root, and the router retries the restore for up to 800 ms until the page is tall enough (stops if the user scrolls).
- Acceptance recorded in `docs/phase1-acceptance.md`.

## 2026-10-18 · Year always listed in the Index

- Fernando asked whether the future log should be a default collection so the Pending panel can find it. Decision: no. The Year keeps its own kind (`future`) with a deterministic id (`future:YYYY`) and month slots (`YYYY-MM`), which is exactly what the panel's category C query needs; a collection has no months. An unwritten Year has no entries, so there is nothing to find.
- Because the future log is "always on", the current year's Year is now pinned at the top of the Index even before anything is written. It is a link only; nothing is stored.

## 2026-10-18 · List numbers read like bullets

- A leading list number (`1. `, `12) `, up to 3 digits, followed by a space) is styled like a bullet: semi-bold, in the bullet color. On a plain text line it colors like a task (Fernando's example), so its children inherit that color; on a task/event/note it takes that item's color.
- The number stays part of the text: stored and exported exactly as typed. The editor renders it in a `.num` span and rebuilds the line's text (keeping the caret) only when the number appears, changes or goes away.

## 2026-10-18 · Numbered lists behave like lists

- **Enter on a numbered item** starts the next line with the next number (`2. …` → `3. `). Enter on an empty item (`3. ` alone) ends the list.
- **Enter at the end of a collapsed item** puts the new line after everything hidden inside it, as the next sibling, and the item stays collapsed (it used to expand it and slip the line in among its children). On an open item with children, Enter starts a new first child.
- **Automatic renumbering** — Fernando's explicit exception to principle 1 (recorded in CLAUDE.md 2.1). After a structural edit (Enter, delete, join, indent/outdent, paste) consecutive numbered siblings are renumbered from the list's first number and separator; a plain sibling ends the list; nested lists count separately. An item indented into a new nested list starts at 1. Typing a number by hand is never overridden while typing. Only the number changes.
- **The user's numbers win** (follow-up from Fernando): before each structural edit the editor notes which items were *not* following their previous sibling + 1 (the first item of a list, or a number typed out of sequence such as `10.` after `2.`). Renumbering keeps those numbers and counts on from them (`10.`, `11.`, …); only the in-sequence items are renumbered. `listRestarts` + `renumberLists` in `src/editor/lines.ts`, unit tested.

## 2026-10-18 · Phase 2: sync with Dexie Cloud

- **Database:** `https://zsu6nu12q.dexie.cloud` (`src/data/cloud.ts`). `requireAuth: false`: the app works fully without signing in (local-first); sync starts after "Sign in" in Settings (email + one-time code, Dexie's own dialog for now).
- **Same local database:** `nameSuffix: false`. By default the addon opens a new IndexedDB named after the cloud database, which made existing data look gone in testing (it was untouched in the old database). Now `bullet-life` is upgraded in place (v1 → v2), verified with a v1 database built by hand.
- **Globally unique ids:** synced primary keys must be globally unique. Entries (ULID) and collections (`collection:<ULID>`) already are. The deterministic time-log rows (`daily:2026-10-18`, …) are dropped in the v2 upgrade: nothing needed them (everything about a time page comes from its date) and entries keep referring to the page by that name. Settings stay per device (`unsyncedTables`), a single fixed row; revisit for the commercial version.
- **Editors only write what they changed:** each editor keeps a base (what it loaded or last saved) and saves only lines it touched; it deletes only lines it knew and removed. Before this, an editor that had not yet received a change from elsewhere wrote the whole page back and undid it (reproduced with two windows). `touchedIds` + `diffEntries(..., base)`, unit tested.
- **Live updates:** each editor watches its stored entries; when they change from elsewhere it reloads, but never while the user is typing (waits for a 2.5 s pause, keeps the caret in the editor).
- **Indicator:** Settings › Sync shows "Up to date", "Syncing…", "Offline…" or "Sync paused" with the signed-in email, plus Sync now and Sign out. On every page a small ring on the Index button appears only when offline or paused; nothing when in sync or not signed in.

## 2026-10-19 · Backup (before Phase 3, at Fernando's request)

- Sync is replication, not backup: a deletion or a bug spreads to every copy. Two protections added now; an automatic off-device copy (Dexie Cloud export on the Mac, or a small service on Railway) is planned for Phase 5.
- **Daily snapshots:** once a day (3 s after launch and when the app returns to the foreground) a full copy of entries and collections goes into a separate local database, `bullet-life-backups`, which is never synced. The 30 newest are kept. Each device has its own.
- **Restore** (from a snapshot or a file) replaces the current content exactly, and first saves a "Before restore" snapshot of the current state (5 newest kept), so a restore can be undone. Confirmation is inline.
- **Export everything:** a JSON file (`bullet-life-YYYY-MM-DD-HHMM.json`, format 1) with entries and collections, without the sync service's fields (`realmId`, `owner`). iPhone: share sheet (Save to Files / iCloud Drive); Mac: download. "Last export" shown in Settings. **Restore from a file** validates the file first and refuses anything that is not a backup from this app (or from a newer format).
- The full Markdown export arrived with Phase 3 (see below).
- Pure rules in `src/data/backup.ts`, unit tested.

## 2026-10-19 · Phase 3: Export, Copy As, Share

- **Where:** a "…" button on the title row of every page (Day, Week, Month, Year, collection). The time header is already full at iPhone width, so the menu sits beside the title instead.
- **Menu:** one panel, no submenus. Scope (Whole page / Selection · N lines, only when there is a selection), format chips (Markdown / Rich Text / Plain Text, the last choice remembered on the device), then Copy, Export, Share. Copying a page in Markdown is 2 taps ("…", Copy).
- **Built from the model, never the screen:** the document is read from the stored entries (`src/export/pageDoc.ts`), so collapsed children are always included. The Month exports its written day rows as `## 18 Sun` sections plus Month tasks; the Year exports its written months. Empty sections are left out; the layout itself is not "content".
- **Prepared on open:** Safari only allows clipboard and share right after a tap, so opening the menu flushes pending edits (`src/pages/flush.ts`) and builds the document; the buttons then run synchronously inside the tap.
- **Copy:** `ClipboardItem` with `text/html` + `text/plain` for Rich Text (plain fallback for apps that only take text); fallback to a `copy` event with `DataTransfer`. **Export:** iPhone opens the share sheet with the file (Save to Files), Mac downloads it. **Share:** `navigator.share` with text; hidden where it does not exist.
- **Selection:** stored on every `selectionchange` as whole lines (with the collapsed children of a collapsed last line) because tapping "…" on iOS can clear the native selection; cleared on navigation. A selection exports as bare lines without the page title, the same as ⌘C.
- **⌘C / iOS Copy / cut** are intercepted when the selection spans lines or covers the whole text of a collapsed parent: the clipboard gets plain text and HTML from the model, children included. A few words inside one line keep the native copy. Cut removes what it copied, hidden children included.
- **Settings:** Markdown glyph style (Checkboxes / Dot notation). Backup › Export everything as Markdown: every written page in one `.md` file (Years, Months, Weeks, Days oldest first, then collections by name). The JSON file stays the restorable backup.
- To validate on the iPhone: rich-text paste into Notes/Mail, the share sheet, and the selection surviving a tap on "…".
- **Paste back into the app** (Fernando's report: pasted items came in as literal "•" and struck characters). ⌘C/iOS Copy now also carries the exact lines (`application/x-bullet-life-lines`); on paste the editor recreates them as entries (fresh ids, indentation relative to the line pasted on). Without that type, text that looks like our export (Markdown with checkboxes or dot notation, or plain text with glyphs) is read back too (`src/editor/paste.ts`, tested). Plain text cannot tell a done/migrated event from a task, so those come back as tasks; Markdown keeps it. Ordinary text keeps the regular paste. Pasting is the user's own gesture on the page they are on, so it is not an automatic copy (principle 1).

## 2026-10-19 · Phase 4: Open items and rituals

- **Name:** the panel and its button are "Open items" (Fernando). Swipe right marks `>`, left marks `<` (Fernando confirmed the default); Settings › Reverse swipe directions flips it.
- **Derived, never stored** (`src/data/openItems.ts`, tested): A = open tasks (and events with Event states on) on a Day/Week/Month whose period has ended; B = marked `>`/`<` with `placement.status = pending`, on any page; C = open Year items whose month has come (or `dueDate` passed). Notes and free text never. Grouped by page (Year items by month), oldest first, coarser page first on the same date; label + age ("Wk 41 · Oct 5 – 11 · last week").
- **Only single-entry writes:** tap the bullet (open → done → cancelled → open), long press / right click for a states-only menu, swipe for `>`/`<`, and "I wrote it there" (placement → placed). No select-many, clear-all, copy or drag. Items acted on stay listed with their new state until the panel closes, so a second tap can still cancel; then resolved ones are gone.
- **Suggested destination** (read-only, toast with "Open"): `>` → the next period of the same log, or the current one for an item left behind; if that level is off, the finest active log; from the Year, this Month; from a collection, the finest log. `<` → the Year, at the first month after the item. Nothing is ever written there.
- **Horizon** setting deferred: without a date on the entry there is nothing to compare N periods against. Revisit if dates on entries arrive.
- **Mac shortcuts:** ⌃⌥→ migrate, ⌃⌥← schedule. The spec's ⌥→/⌥← are the macOS "move by word" keys in any text field, so they stay with the system.
- **Swipe** (touch only, `src/editor/swipe.ts`): horizontal after 10 px, commits at 72 px, reveals the glyph and the destination behind the line; marking again takes the mark back. Lines use `touch-action: pan-y`. The Mac uses menu and shortcuts (trackpad swipes belong to the browser).
- **Layout:** ≥ 1000 px the panel is a 380 px column beside the page (page stays editable); below, a sheet from the right that closes with ×, a tap on the backdrop, or a swipe right outside the rows. Tapping an item opens its page and flashes the entry (the sheet closes on iPhone; the column stays on Mac).
- **Set up banner:** on pages of the current period, "October isn't set up yet" / "Week 43 isn't set up yet" (month first). "Set up" records a small row (`setup:<ULID>`, `periodLogId`) so every device knows; the page stays empty; then it opens that page and the panel. Entries on the page also count as set up. Dismiss is per device and per period.
- **Close the day:** from 20:00 by default (time and on/off in Settings), on current-period pages when Day is active. Opens tomorrow's page with the panel filtered to what is still open today ("Show all open items" removes the filter). Dismissed for the day once used.
- **Count:** plain number beside the button (Settings › Show the count), no badge.

## 2026-10-19 · Due dates (Fernando's request)

- **Writing:** `due:` + `2026-10-23`, a short date (`23/10`, this year; Settings › Date format decides day or month first, and a date that only makes sense the other way round is read that way), `today`, `tomorrow`, `yesterday`, a weekday (`fri`: the coming one; `next fri`: strictly after today), `next week`, `next month`, `in 3 days/weeks/months`.
- **Stored as typed text** `due:YYYY-MM-DD` once the word is finished (space, Enter, or leaving the editor): a written "tomorrow" must not drift. The text survives sync, copy/paste and Markdown export; `Entry.dueDate` is derived from it on save.
- **Shown as a pill:** calendar mark + "Today" / "Tomorrow" / "Yesterday", else "23 Oct" (or "Oct 23"), with the year when not this one. Month names instead of numbers, so no one misreads it. Tint by urgency (overdue red, today amber, later blue), muted on finished items. The pill is atomic: the stored text sits inside, invisible, so the line reads back unchanged; tap it for the system date picker; Backspace removes it whole.
- **Open items:** a **Due** group on top: any open task (or event with Event states) dated today or earlier, on any page, nearest date first, with the page it lives on.
- **Sorting, on request only:** a list of two or more sibling bullets with at least one date that is out of order shows a small sort mark on its first line. A tap sorts it by date (cancelled ones too), undated items last in their order, children with their item; Undo puts it back. Reordering within the page is allowed by principle 1; the app never sorts on its own.
- **Bug fixed on the way:** when lines moved, order keys of lines that did not move could be reassigned but not saved, so two lines could share a key and the stored order differed from the page. `diffEntries` now writes every line whose key changed (regression test).
- Commercial note: the date format default should come from the device region; for now DD/MM per CLAUDE.md.

## 2026-10-19 · Phase 4b: recognizing a rewritten item (trial; remove if noisy)

- When a task or event line is finished (Enter, or leaving the editor), its text is compared with the open items on other pages (`src/data/similar.ts`, tested): lowercase, no accents, no punctuation, no `due:` dates, English and Portuguese stopwords removed; a match is the same words, or ≥ 2 shared words with Dice ≥ 0.7. It errs on the side of silence.
- A strong match shows a quiet chip under the line: "Looks like the open item “…” (Mon, Oct 12)." with **Link it** and ×. Nothing is linked without the tap. Link it sets the original to `>` if it was still open and `placement = placed` with `placedEntryId` = the new line. × remembers the pair on this device and never suggests it again. Editing the line removes the chip.
- Local only, no AI, no network.

## 2026-10-19 · Phase 5: search, Index, shortcuts, accessibility

- **Search (⌘K, or the search button in the Index header):** every entry on every page, collapsed children included, and collection names (`src/data/search.ts`, tested). ## Pen mode, stage 1 (ink without transcription)

- Ink lives on the entry it was written on (`Entry.ink.strokes`), not in a separate table: it syncs with the entry, deleting the entry deletes it, and stage 2 can put the transcription in `text` of the same entry. A stroke is `{k: 'w'|'d', c: color token, r: row, p: [x, y, pressure, ...]}`; x from the sheet's left edge (the gutter included, so drawn bullets stay put), y from the entry's top; points rounded to 0.1 px.
- One ruled line (40 px) = one entry. A writing stroke goes to the row of its middle (an accent written right after a stroke on the next row stays with it); rows an entry takes = rows its writing was on (descenders don't add one) or every row a drawing covers. Writing below the last line creates blank entries for the skipped rows and a new entry; erasing everything on a line keeps it as a blank line (so nothing below moves up), except the last line.
- `perfect-freehand` draws strokes with pressure (simulated from speed without a pen). The stroke in progress is painted on a fixed canvas (low latency); finished strokes are SVG per entry. The layout takes each stroke immediately, before storage answers, so fast writing stays on its line; Dexie runs the writes in order.
- Palm rejection: pointer events from touch never draw; `touchstart`/`touchmove` with `touchType === 'stylus'` are cancelled so Safari does not scroll on pen strokes.
- The text editor never edits ink: `Line.ink` is carried for display (a preview inside the line) and so a deleted-then-undone line gets its ink back; `diffEntries` keeps the stored ink otherwise. Export writes "(handwriting)" / "(drawing)" for lines with ink and no text yet.
- Pen mode shows on a touch screen ≥ 700 × 600 px (iPad); `localStorage['pen.force'] = '1'` turns it on elsewhere for testing.

## Pen mode, stage 2: transcription (MyScript cloud test)

- Fernando chose MyScript (stroke-based, like the on-device ML Kit planned later). The request follows MyScript's own web client (iink-ts 4.1, `HTTPClientV2`): `POST https://cloud.myscript.com/api/v4.0/iink/recognize`, headers `applicationKey` and `hmac` = HMAC-SHA512(body, key = applicationKey + hmacKey) in hex, `Accept: text/plain`; body `{configuration: {lang, text, export}, scaleX: 0.265, scaleY: 0.265, contentType: 'Text', strokes: [{id, pointerType, x, y, t, p}]}`. Our strokes have no timestamps, so points get evenly spaced times in writing order. MyScript's site is not reachable from the build container: the format was read from the iink-ts source map on npm and checked with a mocked endpoint; the live service is first tried on Fernando's iPad.
- One request per handwritten line (entry), only for lines whose writing changed (`ink.n` = writing strokes last read). Runs after 2.5 s without strokes, when Pen mode closes, when a page opens and when the connection comes back; never blocks writing.
- Structure is read locally by geometry (`src/ink/structure.ts`): the leftmost stroke is a bullet when small, followed by a gap, and shaped as a dot (task), closed loop (event) or dash (note); its strokes are marked `b` and left out of recognition. Indent = how far right the line starts, 36 px per level, capped by the line above. Both only on the first transcription.

- Pen mode shows handwriting, not its transcription; the drawn bullet takes the entry's color, its state shows as ×, > or < over it (cancelled: faded with a stroke through), and a 40 px hit area makes it tap/hold like a typed bullet. Type mode shows the text once there is one (the ink preview only while there is none, and always for drawings).
- Keys live in the per-device settings row (not synced): Settings › Handwriting.

- Strokes that did not come out, and a resting palm that scrolled or zoomed the page (2026-10-27, Fernando's video). The sheet allowed every touch gesture, so a palm (or quick taps read as a double tap) could start a scroll or zoom, and Safari then cancels the pen's pointer; a cancelled stroke was thrown away. Three small changes, all in PenSheet: `.pen-sheet { touch-action: pan-y }` (fingers scroll, no pinch or double-tap zoom); a pen stroke cancelled midway is kept (committed as it is) instead of dropped; and touches on the sheet do not scroll while the pen is down or for 1.5 s after it was last on the page (`PALM_HOLD`). Fingers scroll as before once writing pauses. Untestable here on a real Pencil; checked in Chromium with synthetic pointer and touch events.
- Paragraph split at marks below the baseline (2026-10-28 page): a cedilla ("criança"), commas ("menos,", "não,") and letters written a bit low ("fiquei") were read one ruled line down; below the content that made a new entry, and the next line of the paragraph joined it ("/ fomos" was the comma, "( … - iquei" the f). `strokeRow` now also keeps on the previous stroke's line a stroke written right after it that is not wholly below it (`LastStroke` gained y0/y1); a small mark may also sit a little before it (a cedilla or comma added once the word is done). A word written on the next line under the last word still goes down (it is wholly below).
- Pen diagnostics (Settings › Handwriting, off by default): strokes that sometimes do not come out could not be explained from videos, so the app can log what the pen and the hand send to the sheet (pointer events in the capture phase, touches after Pen mode's handler, scrolls) and what Pen mode did with them (taken by a bullet, ruled line, new entry or joined, cancelled and kept or dropped). A small panel shows the last lines with Copy log. The sheet only subscribes to the on/off state, so logging does not re-render it per event (`src/ink/penLog.ts`, `PenLogPanel.tsx`).
- First diagnostics log (2026-10-29): every pen stroke that reached the sheet was stored (none cancelled or dropped); the failed attempts at an "o" left nothing at all, a 10 s gap before the one that came out. So those strokes never reached the sheet. Diagnostics now also listen on the whole page (pointer and touch events outside the sheet, gesturestart/end, focusin, contextmenu, blur, visibilitychange) to tell whether they land on something else or never reach the page.

## Native app (branch claude/native-app, 2026-10-29)

- Why: in the PWA, iPadOS sometimes does not deliver the pen's touches to Safari at all (diagnostics: failed attempts left no event anywhere on the page, with Scribble on and off). A native app gets every Pencil touch through PencilKit.
- Layout: `native/Core` is the Swift package `BulletLifeCore` (no UI, builds and tests on Linux too); `native/App` the SwiftUI app; `native/project.yml` generates the Xcode project with XcodeGen (the `.xcodeproj` is not committed, so it never conflicts).
- Same data as the PWA: Entry/Log/Ink are Codable with the PWA's JSON field names, decoding leniently (missing fields take defaults). Order keys are a line-by-line port of `fractional-indexing` (base 62, heads A–Z/a–z, "a0" first), tested against vectors produced by the JavaScript library; ids are ULIDs. Week keys and dates are tested against vectors from `src/dates.ts`. The pen's line rules (`strokeRow`, `placeStroke`, `readLineShape`, `onOneLine`) are ported with the PWA's test cases.
- Storage: SwiftData, shaped for CloudKit from day one (defaults on every attribute, no unique constraints, no relationships; ink stored as the PWA's JSON in external storage). CloudKit is off (`cloudKitDatabase: .none`) until the app has a paid Apple Developer team.
- N0's page editor is one SwiftUI TextField per line (return splits the line, prefixes convert, the bullet's context menu does the rest). It is a stopgap: the TextKit page editor is phase N1.
- N2 (Pen mode), first part: `InkPage` (Core, tested) is the PWA's PenSheet and ink operations as pure functions on lines: block layout (typed rows measured by the screen, ink rows, hidden lines skipped), page-coordinate strokes, add (join with absorb, or a new entry after blank lines) and erase (the transcription goes with its handwriting; an emptied last line goes). `PenSheetView` wraps a `PKCanvasView` (`drawingPolicy = .pencilOnly`: the finger scrolls, palm rejection is the system's), with the rules as a pattern-image background and typed lines as labels on whole 40 pt rows. Each new PencilKit stroke is converted to the PWA's format (points, force as pressure, 0.1 pt rounding), placed with `PenRules`, and kept on the canvas unless the layout above moved (then the drawing is rebuilt from the lines). Strokes are matched to their entries by creation date and point count; the vector eraser's removals map back to entries. Undo is the app's own (line snapshots), not PencilKit's, so it always matches what is stored.
- Ahead of N3 and N4, in Core (tested, no UI yet): `Transcription` ports `pendingTranscriptions` / `applyTranscription` (transcribe only unread writing; skip if written on again meanwhile; replace text only while it is the last transcription's, adopt existing text on the first pass; type, indent and the bullet strokes read from the drawing only the first time, indent clamped). `Export` ports `src/export/format.ts` (Markdown with checkboxes or dots, plain text, rich text HTML, selection documents), with `InlineText` for `**bold**`, `*italic*`, `==highlight==`; the PWA's format tests are repeated.
- Native pen ink is PencilKit's `monoline` (even width, iOS 17), drawn at the stored size (toolbar sizes are drawn diameters: 2.7 / 3.5 / 4.5 pt, Fernando's choice; a stroke without `s` is 2.4, as in the PWA format; the tool's width is the size divided by the ratio PencilKit draws at, measured on each stroke). The `pen` ink varies with force and tilt, which the stored points (x, y, pressure) can't reproduce, so strokes thickened when the page was drawn again after a stroke; with even width the stroke as written and as stored look the same. Pressure is still stored, for the PWA format. PencilKit draws a stroke's points larger than the tool's nominal width, so a stroke stores in `s` the size it was actually drawn at (median point size), not the toolbar's value; redrawn from storage it keeps its width.
- N3 (transcription): ML Kit Digital Ink comes through CocoaPods (`native/Podfile`, `GoogleMLKit/DigitalInkRecognition` 9.0.0, as Google's sample; no Swift package exists). `Handwriting.swift` is the only file that imports it (`#if canImport(MLKit)`, so the app builds without the pod) and doesn't import BulletLifeCore (both have `Stroke` and `Ink`). Core makes the jobs (`Transcription.jobs`: writing without the hand-drawn bullet, rows laid on one line from the origin) and stores the result (`Transcription.apply`, the PWA's rules). The page runs it in a `.task` keyed by the page, the mode and the page's writing-stroke total: every stroke restarts it, so it reads after 2.5 s without writing (at once in Type mode); when the model finishes downloading the key changes and it runs again. A transcription that only adds text keeps Pen mode's Undo steps.
- N1 (page editor): one `UITextView` (TextKit 1) for the whole page, as the PWA has one contentEditable: each visible line is a paragraph (collapsed children are left out of the text), indented with the paragraph's head indent; bullets (tap: next state; hold: the bullet menu) and chevrons are views in the margin, placed from the layout manager's line fragments. Typing inside a line is UIKit's; `shouldChangeTextIn` sends whatever changes the structure (line breaks, deleting or replacing across lines, a space at a line start) to `PageEdit`, and the text view's `deleteBackward` sends Backspace at a line start (also at the very top, where UIKit has nothing to delete). The model is the truth: after a structural edit the page's text is laid out again from the lines. Undo is the editor's own `UndoManager`: UIKit's typing steps and the editor's structural snapshots go into the same stack, and they stay valid because a snapshot restores exactly the text the view had; a change from outside (another page, a transcription, the bullet menu) starts it afresh.
- N4, first part (Month, Year, trail): the page editor gets an embedded mode (no scrolling of its own, sized to its text through `sizeThatFits`, plain text from the margin) and each place to write on a Month or Year page is one embedded editor with its own slot (`SlotEditor`), loaded and saved on its own: nothing is stored until something is written, and the layout (days, week rules, month names) is drawn from the date. Month day rows fit a phrase on one line by shrinking its font (to 85%, at least 14 pt) before it wraps, as `fitText.ts` does. The trail comes from `Period.anchor` (today inside the period, else its first day) and `Period.trail` in Core.
- Open items (native): `OpenItems` in Core is the PWA's query; the panel reads every entry through a SwiftData `@Query`, so it follows what is written on the pages as it is saved. It is an `.inspector`: a column beside the page on iPad, a sheet on iPhone. Its only writes are one entry's state or placement (`Repository.update`), which posts `changedOutside`; the page (or Month/Year slot) showing that entry loads again, so its next save never writes back the state it showed before. `Outline.diff` now sets `placement` pending on > and < (and clears it otherwise) and keeps `dueDate` from the text, as convert.ts does.
- Index and collections (native): where the notebook is open is a `Place` (a time page, the Index, or a collection) kept by `RootView`; time pages still get a `Period` binding (the last one is remembered, so leaving the Index goes back to a period page). A collection is a free page like Day and Week (`PageView` with a `collection`, so Type, Pen and transcription work the same), with its own header (back to the Index, its name editable in place). Collections are created only from the Index's "New collection" and listed alphabetically through a `@Query`, pinned ones at the top under the current Year.
- N4, the rest: navigation is a `Navigator` (place, history for Back, `focus` to scroll a Month/Year to where you came from, `highlight` to mark an entry opened from Open items). Active logs are three device settings (`logMonthly`, `logWeekly`, `logDaily`), with `ActiveLogs` in Core keeping one on and deciding where Today, a day number and a month name lead. Banners sit in the page's top safe area; "Set up" writes a `setup:` log naming its period, as the PWA. The page menu builds documents from the stored entries (`PageDocs`, `PrintPages`) and hands files and text to the system share sheet (Save to Files, Print, AirDrop); the PDF is drawn with `UIGraphicsPDFRenderer` (A5, ink as vector paths scaled from the pen sheet). Floating controls use Liquid Glass (`glassEffect`) behind `#if compiler(>=6.2)` and `#available(iOS 26)`, so the project still builds with older Xcode and runs on iOS 17.
- Typing speed (native): a page is written 0.7 s after the last change (`PageSaver`), and at once when the page changes, leaves the screen or the app goes to the background; saving on every key read, compared and wrote the whole page each time. Open items reads entries without their ink (`EntryRecord.light`): the button's count follows every save, and decoding every stroke of the notebook each time made typing and moving between pages slow. A state changed from Open items is patched into the open page's lines instead of reloading it, so a write still pending never puts the old state back.
- Editor polish (native): after every change the editor makes sure each line still looks like its type (`restyle`): UIKit types with the attributes around the caret, and Scribble and keyboard suggestions bring their own, which left a heading half body text and Scribble text over a new bullet. It is skipped while text is composed (marked), and the prefix Scribble wrote waits for that too. List numbers are drawn like bullets (bold, the root's color); signifiers sit just left of the bullet. Colors from `Theme.ui` are cached, so comparing them tells whether a line already has its look. Copy puts the exact lines on the pasteboard (`app.bulletlife.lines`) next to rich and plain text; Paste reads them back as entries, or reads Markdown and plain text with bullets (`Paste`, ported from paste.ts with its tests). Deleting a collection asks twice and removes what was written in it.
- Floating headers (native, Fernando's ask): a time page's or collection's header floats over the page, which scrolls under it, seen through a thin material whose blur fades out at the lower edge (`HeaderBlur`). Day, Week and collections measure the header and give the text view or the pen canvas that much top content inset; Month and Year put it in the scroll view's top safe-area inset. The pen toolbar uses the clear Liquid Glass variant, so the page shows through it.
- Ink in Type mode (native): a line's drawing, or its handwriting until it is transcribed, is drawn by a view over the text view, in room the line's paragraph keeps above its text (`paragraphSpacingBefore`), so the text stays exactly the line's text (no attachment character to map around). `InkPreview` in Core decides what shows and its size (handwriting at 70%; a drawing at its stored width, or 60% + 20 capped at 240 + 20, as the PWA). A drawing is selected with a tap; then its corner sizes it, dragging moves it sideways, and × deletes it (as do Backspace on its empty line and Delete while it is selected); size and offset go to `ink.view`, which Pen mode ignores. Moving a drawing to another line is not done yet.
- Due dates (native): `Due` in Core is due.ts (parse, resolve, label, status, runs, sort) with its tests. The editor resolves "due:<words>" when a space, punctuation or Return finishes it. A stored "due:YYYY-MM-DD" stays in the text (export and search see it) but is drawn small and clear, with a pill (`DuePillView`) over it: "Today", "Tomorrow", "23 Oct", colored by urgency; tapping it opens an inline calendar in a popover and writes the new date into the same token. A run of sibling bullets whose dates are out of order shows a quiet "Sort by date" above it; sorting happens only on that tap.
- Lasso and the drawn bullet (native, closing N2): the lasso is PencilKit's own `PKLassoTool` (the system's selection, drag and edit menu) rather than a drawn loop. A move comes back as the same strokes in new places; each is matched to its entry by its key, the shift of its first point is applied to the stored points (pressure kept), and `InkPage.move` (Core, tested; repo.ts moveInk) files them onto the line they were dropped on, or a new line, in one Undo step. Emptied lines stay blank, and every line that lost or gained writing is transcribed again (`n` cleared). Deleting from the lasso menu is the eraser's path; a duplicate or paste is dropped (the page is drawn again from what is stored). Bullets on the sheet, typed and hand-drawn, get finger-only tap targets over the ink (a tap moves the state on, holding opens a menu with type, Migrate/Schedule and signifiers); a tap of the pen stays writing. A handwritten task or event shows its state as the PWA does: its drawn bullet hidden under ×, > or < when done, migrated or scheduled, its words faded when done or cancelled, and struck through when cancelled.
- Lasso follow-up (Fernando): after a move the canvas is no longer drawn again when nothing above moved; only the strokes' owners are remapped, so PencilKit's selection stays around the moved strokes and can be dragged again. When the page must be drawn again (lines shifted, Undo), the tool is switched off and on first, so no selection is left behind where the old strokes were (dragging that ghost duplicated them). The canvas's tool is set only when it changes, and while the lasso is the tool a transcription updates the sheet without redrawing the ink (its colors follow when the tool changes). Under the eraser and the lasso the toolbar shows no size or color as chosen; picking one returns to Write or Draw, whichever was last.
- Bold, italic, highlight (native): stored as Markdown marks in the text, as in the PWA, so export, search and sync see them. `InlineText.runs` (Core, tested) gives the editor UTF-16 runs: formatted words (bold/italic traits on the line's font, highlight as a background) and markers, hidden (a near-zero font, clear) unless the caret or selection is in their span, then faint. `InlineText.toggle` is LineEditor's wrap (⌘B `**`, ⌘I `*`, ⌘⇧H `==`; marks already around the selection come off). The text view allows editing attributes only so the system's Format menu (Bold, Italic) appears; those actions are overridden to write the marks, and Underline is not offered. Month rows that shrink to fit keep each run's traits and leave hidden markers hidden.
- Moving a drawing to another line (native): dragging a selected drawing follows the finger both ways; past 16 pt up or down, a thin rule in the caret's color marks the gap between lines nearest the drawing's middle (`gap(atY:)`, from the layout manager's line fragments). Dropping moves the drawing's line with its sub-items there (`PageEdit.moveLine`, Core, tested; LineEditor.tsx moveLine: never deeper than one level under the line above) and keeps its sideways place, in one Undo step. Text does not wrap around drawings: the drawing keeps its own line, above that line's text.
- Theme, palette, done animation (native): every app color is a dynamic `UIColor` (`Theme.ui`, cached by token) whose provider reads the trait's light/dark and the stored theme and palette, so UIKit and SwiftUI share one source. The choice is read again from `UserDefaults.didChangeNotification` the moment @AppStorage writes it. Paper, Graphite and Night hold the window's `overrideUserInterfaceStyle` (Automatic leaves it to the system); Night is dark with the PWA's black tokens. Text already laid out keeps the colors it resolved, so a change re-identifies the page (`.id(theme/palette)`) and it is built again. Rich Text takes the palette's light colors (`Export.Colors`), as the PDF already did. Done animations are the PWA's (timings ×1.4, cancel quieter) redone in Core Animation (`DoneFx`): the cross stamped, the check revealed by a growing mask; Pop scales the bullet; Ripple and Sparks are short-lived layers; Highlighter is a band under the text view's text; Settle moves a snapshot of the words over a patch of paper. Reduce Motion skips them. They play on the bullet tap and ⌘↩ in Type mode; Settings has a sample task to try them.
- Two pages and the open book (native, Fernando: elegant and native, not a port): one toolbar menu (a system `Menu` with a `Picker`, so exactly one of One page / Two pages / Open book is checked) replaces the PWA's two exclusive buttons; it only shows at regular width. Each page is a `NotebookPage` over its own `Navigator`, passed as the environment object, so every page view, header and editor works unchanged. The second page keeps its own place and history for the session; its Back and Index sit in a small interactive Liquid Glass capsule at its corner, as the window toolbar belongs to the first page. Open items opens entries on the second page (CLAUDE.md 4.2) unless that page is the first page's. The same page is never open in both (two editors would save over each other): the second shows a quiet note instead. The open book's right page is the left page's period moved by one, built with the left page's navigator (tapping a day or month on it moves the left page) and the `.facing` page role, under which the time header shows only the page's name; `pageStep` makes ‹ › turn two pages. A Month alone at 900 pt or wider sets its days and Month tasks side by side, as the PWA; `pageBeside` keeps it in one column next to another page. Flowing text is not built: it needs the editor split across columns.
- Open items with two pages: the page last written on (typing began in its editor, or the pen wrote on it) posts `writingOnPage` with its role; an entry opens on the other page, or on the page being written on when the entry is already there (it is just marked).
