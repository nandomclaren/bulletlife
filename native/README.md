# Bullet Life — native app (iPad and iPhone)

The plan and the decisions are in `CLAUDE.md`, section 17. This folder holds:

- `Core/` — `BulletLifeCore`, a Swift package with everything that does not depend on the screen: the data
  model (the same JSON as the PWA), dates and week numbers, rapid logging, the state cycle, order keys,
  and the pen's line rules. It builds and tests anywhere (`swift test`), also on Linux.
- `App/` — the SwiftUI app.
- `project.yml` — the Xcode project, generated by XcodeGen (the `.xcodeproj` is not committed).

## Build and run on your iPad

1. Install XcodeGen once: `brew install xcodegen` (Homebrew: <https://brew.sh>).
2. In this folder: `xcodegen`, then `pod install` (see Handwriting recognition below), then
   `open BulletLife.xcworkspace`.
3. In Xcode, target **BulletLife** › **Signing & Capabilities**: choose your team (your Apple ID works).
   If Xcode says the bundle identifier is taken, change it there (or in `project.yml`, then run
   `xcodegen` again), e.g. `com.<yourname>.bulletlife`.
   To keep the team when the project is generated again: `export DEVELOPMENT_TEAM=<team id>` before
   `xcodegen` (the id is in Xcode › Settings › Accounts).
4. Connect the iPad (or pick it over Wi-Fi), choose it as the run destination, and press ⌘R. The first
   time, the iPad asks to trust the developer: Settings › General › VPN & Device Management.
   iPadOS also asks to turn on Developer Mode (Settings › Privacy & Security).

With a free Apple account the app stops opening after 7 days; running it from Xcode again renews it.
iCloud sync needs the paid Apple Developer Program (phase N5).

## Build and run on your Mac

The Mac app is the same code as a Mac Catalyst app, optimized for Mac (Mac-sized text and controls, the Mac's
menus, ⌘, for Settings). It has no Pen mode (the Mac has no pen) and doesn't read handwriting (ML Kit has no
Mac build): handwriting written on the iPad shows as it was written, with the text the iPad transcribed.

1. As above: `xcodegen`, `pod install`, open **BulletLife.xcworkspace**.
2. Pick the **BulletLife Mac** scheme and **My Mac** as the destination; in target **BulletLife Mac** ›
   Signing & Capabilities choose your team (or "Sign to Run Locally").
3. ⌘R. The app lands in Xcode's build folder; to keep it in Applications: Product › Archive is not needed —
   Product › Show Build Folder in Finder › Products › Debug-maccatalyst › drag **Bullet Life** to Applications.

Until iCloud sync (phase N5) the Mac app keeps its own notebook. To move the notebook between devices: on the
one you were writing in, Settings › **Export everything** (on the Mac it asks where to save: iCloud Drive is
easiest); on the other, Settings › **Import a backup file…**. Importing replaces everything on that device,
so write on one device at a time.

## Handwriting recognition (ML Kit)

Handwriting becomes text with Google ML Kit, which is only distributed through CocoaPods. Once:
`brew install cocoapods`. Then, in this folder, after every `xcodegen`: `pod install`, and open
**BulletLife.xcworkspace** (not the `.xcodeproj`). Without the pod the app still builds; handwriting just isn't
read (Settings › Handwriting says "Not in this build yet"). The language model (~20 MB) downloads the first
time; after that it works offline. ML Kit has no build for the Simulator on Apple silicon Macs: run on the iPad.

## Bring your data over

In the web app: Settings › Backup › **Export everything** (a `.json` file). Put it where the iPad can see it
(Files, iCloud Drive, AirDrop), then in the native app: Settings › **Import a backup file…**. It replaces
what is in the native app; the web app keeps its data.

## Tests

`cd Core && swift test` (or ⌘U on the BulletLifeCore package in Xcode). The cases are the PWA's, so both
apps place and read things the same way.
